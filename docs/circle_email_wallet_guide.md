# The Definitive Guide: Circle Email-Controlled Wallets (OTP-Based)
> *Solving the "Missing OTP Modal" and successfully onboarding users via Email.*

While PIN-based wallets are standard, Email-OTP wallets offer a smoother Web2 experience. However, the integration flow is significantly different and often poorly explained. This guide covers the working implementation discovered for ArcWork.

---

## 🏗️ Architecture Overview
1. **Developer Console**: You must enable **Social/Email Login** in `Wallets > User Controlled > Configurator`.
2. **Backend**: Fetches a **Device Token** (not just a user token).
3. **Frontend**: Uses `verifyOTP` to trigger the Circle native UI modal.

---

## 1. Backend: Requesting the Device Token
The Email flow starts by identifying the user's **Device** before identifying the user.

**Endpoint**: `POST https://api.circle.com/v1/w3s/users/email/token`
**Payload**:
```json
{
  "idempotencyKey": "uuid-v4-here",
  "email": "user@example.com",
  "deviceId": "unique-id-per-browser-session"
}
```
**Response**:
- `deviceToken`: Required for SDK initialization.
- `deviceEncryptionKey`: Required for SDK initialization.
- `otpToken`: Generated by Circle, used internally to track the OTP session.

---

## 2. Frontend: The OTP Challenge
This is where most integrations fail. You must use the SDK to **wait** for the user to enter the OTP.

### Step 2.1: Initialize the SDK
Instead of `userToken`, we use `deviceToken`.

```javascript
import { W3SSdk } from '@circle-fin/w3s-pw-web-sdk';

const sdk = new W3SSdk({
  appSettings: { appId: "your-app-id" },
  authentication: { 
    deviceToken: "from-backend", 
    deviceEncryptionKey: "from-backend" 
  }
});
```

### Step 2.2: Verify OTP (The "Modal" Trigger)
Calling `verifyOTP` is what triggers the native Circle modal.

```javascript
sdk.verifyOTP(otpToken, (error, result) => {
  if (error) {
    console.error("OTP Failed:", error);
  } else {
    // result.userToken is now available!
    // Store this userToken for the next steps (initialize wallet).
  }
});
```

---

## 3. Creating the Wallet (Standard Challenge)
Once you have the `userToken` from the OTP result, the rest follows the standard PIN flow.

1. **Backend**: Call `/user/initialize` using the `userToken`.
2. **Frontend**: Call `sdk.execute(challengeId)` to set the PIN (Circle currently requires a PIN even for Email users to protect the keys).

---

## 🔑 Common Pitfalls & Fixes

| Problem | Likely Cause | Fix |
| :--- | :--- | :--- |
| **Modal doesn't open** | Authentication mismatch | Ensure you initialized the SDK with `deviceToken` (NOT `userToken`) before calling `verifyOTP`. |
| **OTP not received** | Console Config | Ensure SMTP settings are configured in the Circle Console. |
| **Invalid Device ID** | Reuse of ID | The `deviceId` should be stable for the session but unique enough to identify the browser. |
| **Session Expired** | Timing | The `otpToken` is short-lived. Trigger the modal immediately after the backend returns the token. |

---

## 🚀 Pro-Tip
Use `await sdk.getDeviceId()` to let the SDK generate a consistent ID for the browser. **Crucial:** Note that this method is asynchronous in newer SDK versions—forgetting to `await` it will send an object (the Promise) to your backend, causing a `404` or `API Parameter Invalid` error.
